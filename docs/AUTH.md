# Авторизация: логин/пароль, Telegram, Яндекс, VK

Вход в панель возможен четырьмя способами. Логин/пароль работает всегда,
социальные входы требуют настройки.

> Во всех случаях аккаунт должен **уже существовать** в разделе
> «Пользователи». Социальный вход не создаёт новых админов — он лишь
> опознаёт уже привязанный аккаунт. Это защита от захода посторонних.

---

## 1. Логин и пароль

Работает из коробки. Первый суперадмин создаётся при старте из `.env`:

```
FIRST_SUPERADMIN_EMAIL=admin@example.com
FIRST_SUPERADMIN_PASSWORD=ChangeMe123!
```

Опционально включается 2FA (TOTP) в профиле.

## 2. Telegram Login Widget

### Что делает
Открывает окно Telegram, пользователь подтверждает вход, Telegram отдаёт
подписанные данные. Бэкенд проверяет подпись HMAC-SHA256 токеном бота
(`POST /api/v1/auth/telegram`) — подделать нельзя.

### Настройка
1. В **@BotFather** выберите бота → `/setdomain` → укажите домен панели
   (например `panel.example.com`). Для локальной разработки Telegram требует
   реальный домен, `localhost` не принимается — используйте туннель
   (ngrok/cloudflared) и укажите его домен.
2. В `.env` добавьте **username бота без @**:
   ```
   NEXT_PUBLIC_TELEGRAM_BOT_USERNAME=snews_robot
   ```
3. Пересоберите фронтенд (переменные `NEXT_PUBLIC_*` вшиваются при сборке):
   ```
   docker compose build frontend && docker compose up -d frontend
   ```
4. В «Пользователи» → нужному админу укажите его **Telegram ID**
   (узнать можно у @userinfobot).

### Проверка
На странице входа нажмите «Telegram» → появится официальная кнопка
«Log in with Telegram» → подтвердите. Если пишет «не привязан» — значит у
пользователя не заполнен Telegram ID.

## 3. Яндекс OAuth

### Настройка
1. Создайте приложение на <https://oauth.yandex.ru/client/new>:
   - Платформа: **Веб-сервисы**
   - Redirect URI: `https://ваш-домен/login` (и `http://localhost:3000/login` для локали)
   - Доступы: `login:email`, `login:info`
2. Скопируйте **ClientID** в `.env`:
   ```
   NEXT_PUBLIC_YANDEX_CLIENT_ID=xxxxxxxxxxxxxxxx
   ```
3. Пересоберите фронтенд.
4. В карточке пользователя заполните **Яндекс ID** — либо оставьте пустым:
   при первом входе аккаунт привяжется автоматически, если email в Яндексе
   совпадает с email пользователя в панели.

Схема: implicit flow — токен приходит в URL-фрагменте, фронт отправляет его на
`POST /api/v1/auth/yandex`, бэкенд проверяет через `login.yandex.ru/info`.

## 4. VK OAuth

### Настройка
1. Создайте приложение на <https://dev.vk.com/> (тип «Веб-сайт»).
2. В настройках укажите:
   - Базовый домен: ваш домен
   - Redirect URI: `https://ваш-домен/login`
3. Скопируйте **ID приложения** в `.env`:
   ```
   NEXT_PUBLIC_VK_CLIENT_ID=51234567
   ```
4. Пересоберите фронтенд.
5. В карточке пользователя заполните **VK ID** (или оставьте пустым — привяжется
   по email, если VK его вернёт; для этого запрашивается scope `email`).

Схема: implicit flow → `POST /api/v1/auth/vk` → проверка через `users.get`.

## Частые ошибки

| Сообщение | Причина и решение |
|-----------|-------------------|
| `Не задан NEXT_PUBLIC_...` | Переменная не попала в сборку. Добавьте в `.env` и **пересоберите** контейнер frontend (не просто перезапустите). |
| `Этот Telegram-аккаунт не привязан` | В «Пользователи» не заполнен Telegram ID. |
| `Неверная подпись Telegram` | Домен не совпадает с `/setdomain` в BotFather, либо токен бота в `.env` от другого бота. |
| `Яндекс отклонил токен` | Истёк токен или не выданы доступы `login:email`. |
| Виджет Telegram не появляется | Домен не разрешён в BotFather, либо блокируется расширением браузера. |

## Итоговый чек-лист

```
# .env
NEXT_PUBLIC_TELEGRAM_BOT_USERNAME=snews_robot
NEXT_PUBLIC_YANDEX_CLIENT_ID=...
NEXT_PUBLIC_VK_CLIENT_ID=...

docker compose build frontend
docker compose up -d frontend
```
Затем в «Пользователи» заполните Telegram ID / Яндекс ID / VK ID у нужных админов.
