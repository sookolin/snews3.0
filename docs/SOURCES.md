# Источники новостей: как настроить

Источник — это место, откуда система забирает новости. Раз в заданный интервал
воркер опрашивает источник, находит новые публикации, определяет город,
отбрасывает дубликаты, прогоняет текст через AI и отправляет на модерацию.

---

## Поля и что они значат

### Название
Внутреннее имя. Оно же подставляется в шаблон как `{source}` («Источник: …»).

### Тип
Определяет, каким парсером читать источник.

| Тип | Для чего | Что писать в URL |
|-----|----------|------------------|
| `rss` | RSS/Atom-фиды (самый надёжный вариант) | `https://site.ru/rss` |
| `telegram` | Публичный Telegram-канал | `@channel` или `t.me/channel` |
| `website` | Обычный сайт со списком новостей | `https://site.ru/news` |
| `html` | Отдельная HTML-страница | `https://site.ru/page` |
| `api` | JSON API | `https://site.ru/api/news` |

Для `telegram` читается веб-превью канала (`t.me/s/<channel>`) — канал должен
быть **публичным**. Приватные каналы так не читаются.

### Парсер (движок)
- `auto` — сначала обычный HTTP-запрос; если не вышло, автоматически Playwright.
- `beautifulsoup` / `lxml` — обычный HTML без JavaScript (быстро).
- `playwright` — запускает настоящий браузер Chromium. Нужен для сайтов,
  которые рисуют новости через JavaScript. Медленнее, но «видит» всё.

### Интервал проверки
Как часто опрашивать, в секундах. Минимум 30. Для новостных лент разумно
120–600. Слишком частые запросы могут привести к блокировке.

### Приоритет
Меньше число — раньше попадёт в очередь при одновременной проверке.

### Активен
Выключенный источник не опрашивается.

## Прокси

- **Использовать прокси** — включает проксирование запросов.
- **URL прокси** — формат `http://user:pass@host:port` (поддерживается и `https://`,
  и `socks5://`).

Нужно, если источник блокирует ваш IP или доступен только из определённой страны.

## Заголовки (Headers) — JSON

HTTP-заголовки запроса. Помогают, когда сайт отдаёт 403 обычному скрипту.

```json
{
  "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120 Safari/537.36",
  "Accept-Language": "ru-RU,ru;q=0.9",
  "Referer": "https://site.ru/"
}
```

По умолчанию система уже отправляет собственный User-Agent — переопределяйте
только при необходимости.

---

## Cookies — JSON

Печеньки отправляются с каждым запросом. Нужны, когда контент виден **только
авторизованным** пользователям или сайт требует «согласие с cookie».

```json
{
  "sessionid": "abc123def456",
  "cookie_consent": "accepted"
}
```

### Как получить cookies
1. Откройте сайт в браузере и войдите под своим аккаунтом.
2. F12 → вкладка **Application** (Chrome) или **Хранилище** (Firefox) → **Cookies**.
3. Скопируйте нужные пары «имя → значение» в JSON выше.

Важно: cookies живут ограниченное время. Когда сессия истечёт, парсер снова
начнёт получать 403 — cookies придётся обновить.

## Auth — JSON

Стандартная HTTP-авторизация. Два поддерживаемых варианта:

**Basic (логин/пароль):**
```json
{ "type": "basic", "username": "user", "password": "secret" }
```

**Bearer (токен API):**
```json
{ "type": "bearer", "token": "eyJhbGciOi..." }
```

Bearer превращается в заголовок `Authorization: Bearer <token>` — это обычный
способ авторизации в API.

## Селекторы (Selectors) — JSON

Самое важное поле для типов `website`, `html` и `api`. Оно объясняет системе,
**где именно** на странице лежат новости.

### Для website / html (CSS-селекторы)

```json
{
  "item":  "article.news-card",
  "title": "h2.news-card__title",
  "text":  ".news-card__summary",
  "link":  "a@href",
  "image": "img@src"
}
```

- `item` — контейнер **одной** новости. Система найдёт все такие блоки и обойдёт
  их по очереди. Если `item` не указать, вся страница считается одной новостью.
- `title`, `text` — селекторы **внутри** контейнера.
- `link`, `image` — синтаксис `селектор@атрибут`. `a@href` значит «взять
  атрибут href у тега a». Относительные ссылки достраиваются автоматически.

### Как подобрать селекторы
1. Откройте страницу со списком новостей, F12.
2. Правой кнопкой по заголовку новости → «Инspect».
3. Посмотрите на классы: например `<article class="news-card">` → это `item`,
   внутри `<h2 class="news-card__title">` → это `title`.
4. Проверьте в консоли браузера:
   ```js
   document.querySelectorAll("article.news-card").length   // должно быть > 0
   ```

### Для api (пути в JSON, через точку)

```json
{
  "root":  "data.articles",
  "title": "title",
  "text":  "body",
  "url":   "url",
  "image": "image_url",
  "guid":  "id"
}
```

- `root` — путь до массива новостей. Если API сразу возвращает массив, оставьте пустым.
- Остальные — имена полей внутри одного элемента. Вложенность через точку:
  `author.name`.

## Привязка к городам

В форме источника можно выбрать города. Логика:

- **Города выбраны** → все новости этого источника относятся к выбранному
  городу. Ключевые слова не обязательны (это то, что нужно для «городского»
  источника вроде местного канала).
- **Города не выбраны** → система ищет по всем активным городам по их ключевым
  словам. Если совпадений нет — новость отбрасывается.

Поэтому если вы завели тестовый канал и хотите видеть оттуда всё — обязательно
привяжите его к городу.

## Диагностика

Кнопка **«Проверить»** ставит источник в очередь немедленно. Затем:

- Колонка **«Ошибки»** — счётчик неудач. Наведите курсор, чтобы увидеть текст
  последней ошибки.
- Логи воркера:
  ```
  docker compose logs worker | Select-String source_processed
  ```
  Вывод вида `fetched=3 created=2 duplicates=1 unmatched=0` читается так:
  получено 3 публикации, создано 2 новости, 1 дубликат, 0 не подошли по городу.

### Частые причины «ничего не находит»

| Симптом | Причина |
|---------|---------|
| `fetched=0` | Неверный URL или тип; для сайта — не подошли селекторы. |
| `unmatched=N` (всё) | Нет совпадений с ключевыми словами города. Привяжите источник к городу или расширьте ключевые слова. |
| `duplicates=N` (всё) | Эти публикации уже были загружены ранее — это нормально. |
| Ошибка 403 | Нужны Headers (User-Agent) и/или Cookies. |
| Ошибка Playwright | Сайт слишком медленный — увеличьте таймаут. |
